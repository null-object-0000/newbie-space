# 2026-03-04 Java 代码是怎么运行起来的？

> 从你敲下 `java Main.java` 到程序输出结果，中间经历了什么？

Java 代码的运行主要经历 **编译、类加载、执行** 三个阶段。下面按这个顺序说清楚。

---

## 一句话概括

**源码（.java）→ 编译成字节码（.class）→ JVM 类加载进内存 → 解释或 JIT 编译成机器码 → 在 CPU 上执行。**

---

## 1. 编译

通过 **javac** 编译器将 **.java** 源文件编译成 **.class** 字节码文件。

- **字节码**是一种与平台无关的中间代码，不直接对应某一种 CPU 指令集。
- .class 文件中包含**指令**、**常量池**、**字段与方法的元数据**等信息，供 JVM 后续加载和执行。

```text
Main.java  --[javac]-->  Main.class（字节码）
```

![编译与跨平台示意](/public/posts/daily-2026-03-04/compile-flow.png)

“一次编写，到处运行”的前提就是：同一份字节码可以在不同操作系统、不同机器上由各自的 JVM 来执行。

---

## 2. 类加载

JVM 通过**类加载器**（如启动类加载器、扩展类/平台类加载器、应用程序类加载器及自定义类加载器）把 .class 文件加载到内存，并完成校验、准备和初始化。

### 2.1 类加载器

| 类加载器 | 说明 |
|----------|------|
| 启动类加载器（Bootstrap） | 加载 JDK 核心类（如 rt.jar） |
| 扩展类/平台类加载器（Extension / Platform） | 扩展目录下的类；**JDK 9 模块化后**称为平台类加载器（Platform ClassLoader） |
| 应用程序类加载器（App ClassLoader） | 加载 classpath 下的应用类 |
| 自定义类加载器 | 用户继承 ClassLoader 实现的加载器，常用于热部署、隔离等 |

![类加载器与 JVM 架构](/public/posts/daily-2026-03-04/jvm-architecture.png)

### 2.2 类加载过程

类加载不只“把文件读进来”，还包括链接和初始化，整体可分为三步：

| 阶段 | 做什么 |
|------|--------|
| **加载（Loading）** | 查找字节流（从磁盘、网络等），创建 `java.lang.Class` 对象 |
| **链接（Linking）** | **验证**字节码合法性；**准备**：为静态变量分配内存并赋默认值；**解析**：将符号引用解析为直接引用 |
| **初始化（Initialization）** | 执行类构造器 `<clinit>` 方法，为静态变量赋程序中的初始值 |

![类加载与运行时区](/public/posts/daily-2026-03-04/jvm-architecture.png)

### 2.3 内存分配：运行时数据区

类加载完成后，JVM 根据类信息在**运行时数据区**划分内存，大致结构如下：

| 区域 | 说明 |
|------|------|
| **堆（Heap）** | 存放对象实例和数组，线程共享，GC 主要工作区域。**JDK 7 起**字符串常量池、静态变量已移入堆中。 |
| **方法区（Method Area）** | **JDK 8 之后在 HotSpot 中实现为元空间（Metaspace）**：主要存放**类的元数据信息**。元空间使用**本地内存（Native Memory）**，不占 JVM 堆。注意：静态变量和字符串常量池在 JDK 7 之后已移到堆中。 |
| **Code Cache（代码缓存）** | 存放 **JIT 编译后的本地机器码**，与“方法区里放 JIT 代码”的广义说法对应，实际落在这块独立区域。 |
| **虚拟机栈（VM Stack）** | 每个线程私有，存储**栈帧**（方法调用的局部变量、操作数栈、返回地址等） |
| **程序计数器（PC Register）** | 每个线程私有，记录当前线程执行的**字节码指令地址** |

![JVM 内存布局](/public/posts/daily-2026-03-04/jvm-architecture.png)

此外还有**本地方法栈**（Native Method Stack），与虚拟机栈类似，为 Native 方法服务。

## 3. 执行

JVM 从 **main 方法**开始执行（主线程）。字节码的执行方式有两种：

| 方式 | 特点 |
|------|------|
| **解释执行** | 逐条把字节码翻译成机器码并执行，**启动快**，适合冷代码 |
| **JIT 编译（Just-In-Time）** | 对**热点代码**（如频繁调用的方法、循环）编译成本地机器码再执行，**运行效率高**；编译出的机器码存放在 **Code Cache（代码缓存）** 中。 |

![执行引擎（解释器与 JIT）](/public/posts/daily-2026-03-04/jvm-architecture.png)

两者往往配合使用：先解释执行，同时 JIT 在后台对热点代码做编译，后续再执行就直接用机器码。

### 3.1 方法调用与栈帧

当 **main 方法**（或任意方法）被调用时，JVM 会为其创建一个**栈帧**并压入当前线程的**虚拟机栈**。栈帧里主要包含：

- **局部变量表**：存放方法内的基本类型和引用（指向堆中对象的地址）
- **操作数栈**：执行指令时用到的临时数据
- **其他**：返回地址、动态链接等

**对象实例**在**堆**中分配，**栈中的引用**保存的是堆里对象的地址。也就是说：局部变量表里存的是“引用”，真正的对象在堆上。

## 4. 小结

整体流程可以概括为：

```text
.java 源码
    ↓  javac 编译
.class 字节码（与平台无关）
    ↓  java Main 启动 JVM
类加载：加载 → 链接 → 初始化，并划分堆、方法区、栈等内存
    ↓
执行：从 main 开始，解释执行 + JIT 编译热点代码
    ↓
栈帧入栈、对象在堆中分配，机器码在 CPU 上跑起来
```

![运行全流程](/public/posts/daily-2026-03-04/java-jvm.png)

所以：**Java 代码能跑起来，是因为 JVM 先把与平台无关的字节码加载进内存、完成类加载与内存布局，再通过解释和 JIT 在具体平台上生成并执行机器码。** 编译阶段解决“写一份、多平台用”，类加载与执行阶段解决“在各自机器上怎么跑”。
